# Contributing

Contributions should help explain mixture-of-experts routing, agent aggregation or reproducible evaluation. Keep runnable examples offline by default and label all invented data clearly.

Use synthetic inputs or public material with clear permission and attribution. Do not add production source, prompts, model/vendor configurations, deployment instructions, service analytics, customer content, personal information, authentication material or account exports.

Before a contribution, run `python -m unittest discover -s tests -v` and inspect the complete staged diff. Do not copy configuration or evidence directories into this repository. Research claims should cite primary sources and distinguish a teaching example from a measured result.

The current repository intentionally contains a fresh, self-contained study history. Do not merge earlier repository history back into it. Reapply suitable changes as newly reviewed patches without importing unrelated files or commits.
